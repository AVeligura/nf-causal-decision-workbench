# Предрегистрация вычислительных правил NF-Causal Decision Workbench v2

Дата фиксации: 2026-08-17. Правила ниже определены до просмотра результатов нового
Monte Carlo и не подбираются по сравнительным показателям методов.

## 1. Суммирование α-траектории

α-срезы рассматриваются в порядке от узкого к широкому, то есть по убыванию α. Для каждого
среза сохраняются идентификационный статус, выбранное действие, максимальное сожаление и граф,
впервые добавленный на данном уровне.

Траектория классифицируется следующим образом:

- `robust`: одно ненулевое допустимое действие сохраняется на всех непустых α-срезах, ни один
  существенный компонент его ценности не теряет идентифицируемость;
- `pilot`: траекторийный минимакс выбирает `a1`, чистая ожидаемая ценность информации строго
  положительна, а виртуальная пилотная процедура воспроизводима;
- `conditionally_robust`: одно действие сохраняется на непрерывном диапазоне α, но за его
  границей возникает abstain вследствие потери идентифицируемости или превышения допуска;
- `switching`: среди ненулевых рекомендаций встречается более одного действия;
- `abstain`: существенная ветвь не идентифицирована либо ни одно действие не проходит допуск.

Операционное правило полной процедуры:

1. При `robust` используется устойчивое действие.
2. При `pilot` используется `a1`.
3. При `conditionally_robust` действие выдаётся только вместе с диапазоном α и структурным
   условием; для расчёта безусловной policy value оно трактуется как мотивированный отказ.
4. При `switching` и `abstain` безусловное действие не назначается (`a0` как фактически
   реализуемый безопасный режим при вычислении regret).

Hard-set анализируется один раз по множеству структур, прошедших hard-проверку, без μΓ(G),
ранжирования и истории включения графов.

## 2. Единая ценностная модель

Для действия `a` с охватом `c(a)` применяется одна функция:

`V(a)=m*c(a)*(ΔCFO+w_CR*ΔCR+w_FC*ΔFC+w_AR*ΔAR-w_S*LossSales-w_Z*Pzombie)-Cprogram(a)+I(a)`.

Для оценочной политики компоненты поступают из графоспецифических оценок и их интервалов;
`ΔFC` и `ΔAR` вычисляются по заранее заданным коэффициентам связи, а побочные эффекты — по
параметрам режима. Для oracle truth та же функция получает средние потенциальные исходы и
побочные результаты генератора. Формула, охват, горизонт, веса и затраты совпадают.

## 3. Предрегистрируемые экономические режимы

Состав исходных десяти ячеек не меняется. Каждому сценарию до запуска сопоставляется один из
трёх экономически интерпретируемых режимов.

| Режим | Сценарии | Стоимость программы | Потери продаж | Риск поддержки нежизнеспособных предприятий | Ожидаемый результат |
|---|---|---:|---:|---:|---|
| Благоприятный | reference, evidence_conflict | базовая | низкие | низкий | `a2` может быть оптимальным при достаточном эффекте |
| Пограничный | weak_overlap, version_mixing | базовая/умеренная | средние | средний | допустимы `a0`, `a1` или `a2`; пилот определяется только EVI |
| Неблагоприятный | informative_loss, outside_gamma | повышенная | высокие | высокий | `a0` может быть оптимальным; осторожность не считается ошибкой автоматически |

Параметры генератора, отвечающие за режим: `effect_scale`, `sales_loss_scale`,
`zombie_risk_scale`, `pilot_share`; параметры ценностной модели: стоимости `a1/a2`, веса
потерь продаж и zombie-risk, стоимость информации. Знак причинного эффекта искусственно не
переворачивается.

## 4. Информационная ценность пилота

Для текущего состояния сначала вычисляется минимальное максимальное сожаление без новой
информации. Затем генерируются не менее 50 виртуальных пилотных выборок размера
`round(pilot_share*n_analysis)`. В каждой выборке обновляются графоспецифические достаточные
статистики, повторно вычисляется минимаксное сожаление и фиксируется его сокращение. Чистая
EVI равна среднему сокращению regret минус стоимость пилота. Сохраняются среднее, MCSE,
число симуляций и seed. Пилот не может быть выбран при неположительной чистой EVI или при
невозможности обновления.

## 5. Правила интерпретации времени

`replication_runtime_seconds` и `replication_peak_memory_mb` относятся ко всей репликации и
не сравниваются между методами. `shared_estimation_seconds` относится к общим этапам генерации
и графоспецифического оценивания. `method_decision_seconds` измеряет только добавочную
стоимость построения решения конкретной конфигурации.
