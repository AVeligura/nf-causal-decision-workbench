# Единая ценностная модель

## Спецификация

Для действия `a` с охватом `c(a)` используется:

`V(a) = m·c(a)·(ΔCFO + wCR·ΔCR + wFC·ΔFC + wAR·ΔAR − wS·LossSales − wZ·Pzombie) − Cprogram(a) + I(a)`.

Здесь `m` — масштаб ценности, `Cprogram(a)` — стоимость программы, а `I(a)`
ненулевая только для пилота. Охват `a0=0`, охват `a1=pilot_share`, охват
`a2=1`. Все коэффициенты и затраты передаются через `ValueModelConfig`.

Модуль `src/domain/value_model.py` является единственным местом реализации
формулы. Оценочная ветвь передаёт интервалы эффектов `Y_CR/Y_CFO` и
предрегистрированные преобразования побочных компонентов. Oracle-ветвь передаёт
средние потенциальные исходы генератора:

- восстановление коэффициента покрытия `Y_CR`;
- операционный денежный поток `Y_CFO`;
- сокращение стоимости финансирования;
- сокращение просроченной задолженности;
- потери продаж;
- риск поддержки нежизнеспособных предприятий.

Различается источник входов, но не формула, охват, веса, затраты или горизонт.

## Экономические режимы

Десять утверждённых ячеек не менялись. Сценарии заранее сопоставлены режимам:

- благоприятный: `reference`, `evidence_conflict`; истинный optimum — `a2`;
- пограничный: `weak_overlap`, `version_mixing`; истинный optimum — `a1`;
- неблагоприятный: `informative_loss`, `outside_gamma`; истинный optimum — `a0`.

Различие возникает из заранее заданных затрат, потерь продаж, zombie-risk,
охвата и ожидаемого эффекта. Знак причинного эффекта не менялся после просмотра
результатов.
